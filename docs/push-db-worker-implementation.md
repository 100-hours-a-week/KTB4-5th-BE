# 푸시 DB 워커 구현 메모

2026-10-14. 로컬 구현·자동 실행 연결·격리 E2E 검증 완료 상태이며 운영 배포·DB 마이그레이션 완료를 의미하지 않는다.

## 현재 결정

- 서버마다 워커 하나가 기본 20개의 실행 자리를 관리한다. 전체 서버의 합산 한도는 아니다.
- 선점 기간은 `push.dispatch.lease-duration`, 기본값은 `30s`다.
- `FOR UPDATE SKIP LOCKED`로 ID를 골라 잠그고 같은 짧은 트랜잭션에서 bulk UPDATE로 lease를 기록한다.
- 결과 저장은 작업 번호·PROCESSING 상태·lease 토큰·유효 기한을 조건으로 한 UPDATE다. 변경 건수 0은 소유권 상실 등의 정상적인 건너뛰기 결과다.
- 선점 서비스는 `int`와 검증된 `LeaseDuration`을 받는다. 워커가 설정 Duration을 VO로 변환하고, `SelectedJobIds`가 선택된 번호와 lease 기록 건수 검증을 맡는다.

## 이번에 연결한 전송 흐름

1. `poll()`이 빈자리만큼 선점하고 실제 가져온 개수만큼 카운터를 증가시킨다. 같은 워커의 호출은 `synchronized`로 직렬화한다.
2. 각 작업을 가상 스레드에 등록한다. 등록이 거절되면 즉시 자리를 반납하고, 실행된 작업은 `finally`에서 반납한다.
3. 아직 내 lease가 유효한 작업을 조회한다. 발송 기한 만료, 구독 비활성·버전·소유자 불일치, 수신 자격 상실은 전송 전에 종료한다.
4. 전송 직전 구독을 다시 조회해 해당 버전·소유자의 활성 구독을 사용한다. HTTP 요청 동안 DB 트랜잭션을 유지하지 않는다.
5. 전송 결과를 별도의 짧은 트랜잭션에서 토큰 조건부 UPDATE로 저장한다. 결과가 기록되면 lease 정보는 비운다.

| 결과 | 저장 동작 |
|---|---|
| 제공자 수락 | ACCEPTED, 시도 횟수 증가, 수락 시각 기록 |
| 전송 실패 | 기존 엔티티의 재시도 규칙으로 다음 상태·시각을 계산한 뒤 조건부 UPDATE |
| 구독 사용 불가 | CANCELLED, SUBSCRIPTION_UNAVAILABLE |
| 수신 자격 상실 | CANCELLED, RECIPIENT_UNAVAILABLE |
| 발송 기한 만료 | FAILED, SEND_WINDOW_EXPIRED, 시도 횟수는 증가시키지 않음 |

재시도는 첫 실패 후 5분, 두 번째 후 15분, 세 번째 후 30분이며 네 번째 실패는 종료한다. 다음 재시도 시각이 발송 기한 이상이면 종료하는 기존 규칙도 유지한다. SQL에 재시도 지연값을 복제하지 않는다.

전송 중 구독이 갱신될 수 있으므로, 제공자의 구독 만료 응답에 따른 무효화도 전송한 구독 버전이 아직 일치할 때만 처리한다. 이때의 기기 행 잠금은 응답 이후 짧은 트랜잭션에만 적용한다.

## 실행 연결과 검증

- 8시 배치는 인앱 알림과 푸시 작업 생성 후 반환한다. 전송·재시도 대기 루프는 제거했고 기존 발송 서비스는 자동 실행 경로에서 호출하지 않는다.
- `PushWorkerScheduler`가 기본 1초 간격으로 poll을 호출한다. 생성 배치가 워커의 실행을 막지 않도록 스케줄러 풀 기본값은 2다. DB 선점·HTTP 전송·결과 저장은 기존의 짧은 트랜잭션 경계를 유지한다.
- 푸시·알림 및 애플리케이션 컨텍스트 관련 회귀 테스트 296건 통과(최신 dev 기준). 최종 E2E 5건은 MySQL 8.4.8과 로컬 HTTP 서버로 정상 발송·두 워커의 작업 분리·동시 실행 한도·재시도·만료 lease 복구·예전 토큰 차단·구독 취소·발송 기한 종료를 검증했다.
- E2E의 두 워커는 같은 테스트 JVM 안에서 독립적인 슬롯 객체를 갖는다. WebPushRequestFactory만 테스트용 HTTP 요청으로 대체하며 실제 전송 서비스·HTTP 클라이언트·응답 분류·DB 조회/갱신은 사용한다. VAPID 요청 암호화와 실제 브라우저 수신은 이 E2E의 범위가 아니다.
- 첫 발송·재시도 우선순위, 선점 쿼리 인덱스와 규모별 성능 측정은 후속이다. 토큰은 DB 상태 덮어쓰기를 막으며 제공자 수락 뒤 결과 저장 전에 장애가 발생하는 경우의 중복 푸시까지 보장하지 않는다.

## 배포 및 수동 검증

공통 기본값은 다음과 같다. `NOTIFICATION_EXPIRATION_CRON`은 작업 생성 서버 하나에만 8시 cron을 두고 다른 서버에서는 `-`로 설정한다. 생성 서버가 중단되었을 때의 자동 리더 전환은 구현하지 않았다.

```ini
PUSH_DISPATCH_ENABLED=true
PUSH_DISPATCH_POLL_INTERVAL=1s
PUSH_DISPATCH_CONCURRENCY=20
PUSH_DISPATCH_LEASE_DURATION=30s
SCHEDULING_POOL_SIZE=2
NOTIFICATION_EXPIRATION_CRON="0 0 8 * * *"
```

워커 전용 서버:

```ini
NOTIFICATION_EXPIRATION_CRON=-
```

`PUSH_EXPIRATION_BATCH_ENABLED=false`는 새 푸시 작업 생성만 중단한다. 기존 작업의 워커 처리를 중단하려면 `PUSH_DISPATCH_ENABLED=false`를 사용한다. 인앱 알림 생성과 새벽 3시 정리는 별도로 유지된다.

기존 DDL에 `claim_token`이 있으면 [이름 변경 SQL](database/migrations/2026-10-14-push-lease-token.sql)을 검토해 스키마와 코드를 맞춘다. 이미 `lease_token`인 DB에는 실행하지 않는다. 운영 DB에 직접 적용하지 않았으며, 이 파일은 기존 `ck_push_claim` 제약을 가진 DDL 기준이다. MySQL 8.4.8에서 기존 토큰 보존과 이름 변경 후 CHECK 제약 유지를 검증했다.

로컬의 격리 DB·로컬 HTTP E2E 재실행:

```bash
./gradlew test --tests '*PushWorkerEndToEndTest'
```

## VO·일급 컬렉션 검토안

사용자 요청에 따라 서비스 밖의 객체가 값의 규칙과 묶음의 책임을 맡을 수 있는지 검토했다. `LeaseDuration`과 `SelectedJobIds`를 적용했고 `Lease`는 검토안이다. lease 서비스 인자는 LeaseDuration이며 JPA 매핑은 추가로 변경하지 않았다.

| 후보 | 맡길 책임 | 판단 |
|---|---|---|
| LeaseDuration VO | 생성 시 null·0·음수 거절, 시작 시각으로 만료 시각 계산 | 적용. 서비스의 기간 검증과 종료 시각 계산을 옮김. 작업 수가 0이어도 VO 생성 단계에서 기간 검증 |
| SelectedJobIds 일급 컬렉션 | 선택한 ID 목록의 불변 보관, 개수·빈 목록 판단, 전체 lease 기록 건수 확인 | 적용. 불변 목록 보관, 빈 목록 판단, lease UPDATE 건수 확인을 맡김 |
| Lease VO | 함께 움직이는 토큰·시작·만료 시각 보관, 기한 계산·비교 | 이후 검토. 생성과 DB 매핑 변경 범위를 확인한 뒤 선택 |

작업 수는 최대 동시 실행 한도, 현재 사용량, 조회 요청량, 실제 선점 건수의 규칙이 다르므로 하나의 Count VO로 일괄 포장하지 않는다. 특히 조회 요청량 0은 정상적인 상황이고, 기존 서비스의 음수 입력은 빈 결과라는 동작도 변경 전에 확인해야 한다.

AtomicInteger로 관리하는 실행 자리 카운터는 변경되는 공유 상태이므로 불변 VO로 분류하지 않는다. DB 조회·UPDATE·트랜잭션은 서비스와 저장소의 책임으로 유지한다. 메모리의 VO 검사만으로 토큰 조건부 UPDATE를 대체하지 않는다.

## 실행 자리 객체

`WorkerSlots`가 최대 자리 수와 사용 중인 자리 수를 보관하고 빈자리 계산·점유·반납을 맡는다. 서버 인스턴스마다 하나의 워커가 주입받으며 전체 서버의 합산 한도를 관리하는 객체는 아니다.

- 최대 자리 수는 양수여야 한다. 점유 요청 0은 허용하고 음수 요청·한도 초과 점유·빈 상태에서의 반납은 기존 방식의 CustomException으로 거절한다.
- 점유·반납은 AtomicInteger.updateAndGet 안에서 검증과 변경을 함께 수행한다. 갱신 경쟁으로 값이 바뀌면 최신 값으로 다시 판단하며 연산 함수에서 외부 I/O나 로그 등의 부수효과를 수행하지 않는다.
- 워커의 synchronized poll은 유지한다. 빈자리 확인·DB 선점·점유까지 함께 보호하는 책임과 개별 개수 변경을 원자적으로 처리하는 책임은 구분한다.
- 설정 키와 기본값 20, DB 선점과 전송·결과 저장 흐름은 유지했다. WorkerSlotsTest는 한도 초과·잘못된 반납·동시 점유 40건 중 최대 20건 성공을 검증했다.
